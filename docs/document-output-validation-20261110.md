# 单证填写与输出验收（2026-11-10）

用户已授权把确认后的填写界面落实到正式软件并发布在线更新。本轮以最后确认的原有顶部工具、悬浮计算器、原左侧导航和公司默认资料为边界；早期 Demo 仅保留设计过程参考，不再作为这些控件位置的依据。发布目标版本 v0.11.36。

- PDF 页面改用独立临时文件载入，避免含大图片的长 data URL 触发 ERR_INVALID_URL。保留本机资源 CSP、UTF-8、字体与图片等待、窗口和临时文件清理。
- 统一输出工作台读取当前已编辑 DOM 及各自准备的草稿；单证切换与 PDF 页码分开。支持当前、勾选及全部打印／导出；返回选中单证修改。每份使用独立预览 token，导出字节与预览一致。
- 成功输出后才归档；取消、失败及仅预览不归档。历史重试只补存真正已成功输出的对应单证，不重复输出或误存其他单证。
- 语言拖拽实时让位、取消还原、落位自动保存；保存顺序不会提交尚未保存的配色、文字或语言启停。重新载入后恢复。
- 签名版本、独立签名／公章及适用的收款／详细照片控件移到底部统一显示，保留原事件和快照；顶部标为 PDF语言、PDF颜色。
- PI 按钮改为“填入PI标准付款及运输备注”，确认覆盖当前备注，包含原有完整双语30%／70%、报关文件、PDI、订舱运港及银行／SWIFT提醒；不修改付款比例字段、价格或客户。

## 正式填写界面

- document-form-schema.js 对已有有效字段和字典一次迁移，报价等四类明细独立保存设备／各项费用字段；新配置不再引用旧报价模板。保存时保留单证快照，读取历史原单不改写数据库。
- 八类单证使用各自板块名称；填写顺序直接读取配置排序，条目类型优先，取消必要字段折叠。图片上传在其配置顺序显示，客户扩展字段保持在客户区域。
- 装箱单独立填写包装长宽高、单位、件数、重量、体积、唛头和运输资料；商业发票和装箱单的运输配置与 PDF 同步，兼容读取已有 shipmentDetails。
- 邀请函采用邀请函信息、受邀人信息、来访安排、邀请说明；先选受邀类型，第1人与其他人按序集中填写，多人字段跟随后台排序，国家与大使馆支持中文搜索。
- 保留原海关编码库和自建接口，商品描述建议及中文关键词选码继续可用。付款比例与付款方式分开，后者保留T/T、L/C、USDT、现金等选项。港口管理和下拉字典从对应字段进入。
- 选项使用原字段编辑器逐项管理，独立删除，不把一行多项批量删除；保留字段拖拽、启停、关联字段、更多设置，扩充图标，内部标识只读。
- test-document-form-alignment.cjs 覆盖八类单证的字段重排、先选条目类型、费用条件字段、多人顺序、顶部工具、原导航和重复预览移除。
- test-quotation-config-alignment.cjs 覆盖当前配置优先、配置保存重开、产品导入、自定义值、真实PDF、旧模板不回流，以及正式历史快照不被新配置覆盖。

## v0.11.37 按 Demo 纠正预览与分页

此前把右侧预览入口误做成常驻双栏，和完整 Demo 的独立预览模式不一致。本版填写区恢复全宽，八类单证保留右侧“单独预览”入口，点击后才进入最终 PDF 工作台，填写区右侧和下方都不常驻预览。

复现实际报告的三页单证：保存的竖版被按列数自动切换为横版，银行与签署区的整块避分页进一步增加页数。修复后服从保存的横竖版，银行信息允许自然续页；该实际内容超过一页时正常续到第二页，不再额外生成第三页。客户实际内容仅在本地隔离输出目录验证，不进入仓库。

验证包括八类填写区全宽及原字段顺序、横竖版设置切换、点击入口才生成实际 PDF、返回修改与批量输出。15份实际 PDF 检查确认短单一页、无空白页；十种语言的36行宽表确认多页仅由内容溢出产生，所有货物行完整且不重复。
