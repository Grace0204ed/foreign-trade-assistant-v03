一、实施边界
1. 新图决定页面布局、按钮位置、外观、板块顺序、展开与收起方式，不另起一套设计风格。
2. 具体字段继续由后台配置控制名称、顺序、显隐、必填与选项；不能将图片里的示例列写死，也不能因为截图未显示某列就删除已有配置和历史值。
3. 保留顶部 PDF 语言、PDF 颜色、文字样式及原悬浮计算器规则；保留软件其他页面的左侧导航、应用锁、声明与帮助。
4. 进入制作界面自动收起侧栏，填写区占满可用空间；窗口最大化时继续自适应铺开，不放置常驻右侧或底部预览。
5. 客户、产品、公司、账户、签署资料、历史、草稿及输出快照不得因界面调整丢失。折叠只改变显示状态，不销毁填写内容或断开原事件绑定。
6. 本图是 PI 的具体示例。贸易类单据按适用业务复用其外壳；装箱单保留包装与货物字段，邀请函保留四步流程，授权书和佣金结算单保留各自业务，不强套 PI 的字段与板块。

二、功能逐项盘点
项目｜现有状态｜本次处理
顶部 PDF 语言、颜色、文字样式｜已有｜保留位置与功能，按新图调整间距和控件外观。
八类单证切换、独立资料与保存｜已有｜替换当前“单证工作台”大卡片及说明文字，改成图中顶部紧凑选择带。
勾选多类单证准备草稿｜已有基础｜复用原准备流程，增加一套跨视图一致的选择状态，不能保留两套选择器并行。
“已选 N 项”及其下拉｜当前顶部没有｜新增选中数量、已选列表与统一联动；不与当前正在编辑的单证混淆。
“批量制作”｜已有准备多份草稿的基础｜新增图中顶部入口；检查并适配从 PI 等非报价单开始准备其他适用单证的资料来源。
批量导出 PDF｜预览工作台和历史批量导出已有｜新增图中顶部入口，连接本轮勾选范围，不默认导出所有历史，不重写 PDF 引擎。
左侧返回路径｜已有返回工作台与展开/收起导航按钮｜改成图中左箭头和“新建单证 / 单证填写”路径；移除旧的重复按钮外观，保留返回、未保存提醒及离开后恢复导航的能力。
标题、自动保存状态、恢复上次编辑｜已有｜按图重排；保存时间必须来自真实成功保存结果，不能伪造“已保存”。
单据预览、当前 PDF 导出、新建空白单据｜已有｜按图放到标题行右侧，保留原输出和新建确认流程。
粘贴客户信息识别、编号、日期、客户国家选择｜已有｜按图整理基础信息区，不另造客户数据或下拉管理。
横向明细、条目类型首列、产品库选择、新增、图片、计算｜已有｜采用图中的紧凑行高与间距，维持正常可读字号；富余宽度自适应，必要时仅表格内滚动。
填写表头随单证颜色变化｜v0.11.45 已有｜保留并纳入新样式，不改成固定绿色。
基础信息与明细板块折叠｜本图对应行为未实现｜新增，默认展开，收起与展开不丢字段或上传图片。
付款与交付条款折叠、右侧摘要｜业务字段已有，折叠与摘要没有｜默认收起，显示贸易方式、实际付款比例、实际交货时间；展开后继续使用原配置字段。
独立“售后与质保”折叠栏｜字段已有，目前混在条款中｜只重组呈现，保留字段标识、已有内容与配置，摘要来自实际质保内容。
收款信息折叠、所选账户摘要｜账户管理、选择与快照已有｜默认收起，摘要显示当前实际选择的账户；展开保留公司、账户类别与账户明细。
单据显示设置折叠、开关摘要｜开关已有，折叠摘要没有｜默认收起，摘要实时显示原有开关状态，展开后仍能操作全部适用设置。

三、顶部多选与批量操作预案
1. 顶部只保留一套选择状态。复选框管理批量范围，单证名称用于切换当前编辑对象，不能每次勾选都跳到另一张表或新建空白表。
2. “已选 N 项”、顶部勾选、批量制作及批量导出使用同一范围；预览工作台打开时承接该范围，不能一边选 3 项、另一边默认输出全部。
3. 取消勾选只移出本轮批量范围，不删除已填写的单证、旧草稿或历史。
4. 批量制作复用独立草稿与编号生成规则。对已经填写的草稿不得静默覆盖；尚未准备的单证仅复制适用的客户和货物资料。
5. 当前准备流程以报价单作为货物来源，须补查从 PI、合同等单据开始的场景，不能要求用户先创建报价单才能批量准备。
6. 装箱单只继承适用货物，不继承海运费等费用行；邀请函、授权与佣金使用各自的业务资料规则。
7. 顶部批量导出针对本轮勾选且准备好的单证，沿用统一预览、返回修改、独立 PDF、取消/失败保留内容和成功后正确归档的流程。
8. 批量导出不能将“准备草稿”视为“已签发”，不能因预览、取消或部分失败新增无效历史。

四、按图实施的界面状态
1. 顶部工具行：左侧新建单证标题，语言、颜色、文字样式沿用图示位置。
2. 顶部选择行：八类单证复选项、已选数量下拉、批量制作、批量导出 PDF；取消当前旧工作台的大段说明和重复准备入口。
3. 标题行：左侧返回路径，中间当前单证标题与真实保存状态、恢复按钮，右侧单据预览、导出 PDF、新建空白单据。
4. PI 下方板块顺序：基础信息、明细、付款与交付条款、售后与质保、收款信息、单据显示设置。
5. 基础信息和明细默认展开，下方四栏默认折叠；展开/收起图标、标题、右侧摘要和容器外观依新图实现。
6. 摘要使用实际值，无值时不套用图片里的 FOB、30%+70%、30 天、三个月或示例公司作为业务默认值。
7. 上方“显示图片”对应明细图片，下方“图片”摘要对应原附加照片/照片附页；两者可以分别开启、关闭，不能误合并成同一开关。
8. 未在截图中完整展开的已选列表、折叠内容、错误定位、空选择及窄窗口状态，应先补齐同风格交互 Demo；不新增无依据的业务按钮。
9. 截图角落无文字绿色图标不作为新增业务功能的依据；不自行加入外部品牌图标或替换已有悬浮工具。

五、与前面待修复问题合并
1. 首页慢及先显示不完整旧式页面：单独测量启动与首屏链路，再做最小修复；保持现有最终首页外观。
2. FOB：按用户业务只填写装车地点和中国交货港，不自动要求海运方式、柜型和目的港，也不要求先选海运方式才能显示交货港。
3. 自定义交货时间：编辑完成后在主框直接显示输入原文，例如 30 或 30 day；折叠摘要、草稿恢复及 PDF 同步该实际值，未要求自动补单位。
4. 以上两项条款行为必须接入新折叠板块，不先修出一套旧 UI 后再覆盖成另一套。

六、实施顺序（恢复修改后执行）
阶段 1：完成本预案核对，补齐截图没有展开的同风格交互状态，逐项核对已有按钮与必需操作的保留位置。
阶段 2：复刻公共布局及顶部选择行，替换旧工作台/重复导航外观，接入单一的多选与批量范围。
阶段 3：将现有字段与开关移入折叠板块，增加实时摘要与错误自动展开定位；保持现有保存及事件绑定。
阶段 4：统一修复 FOB、自定义交货时间及首页加载；针对每项分别验证，不顺手改其他模块。
阶段 5：对照原图运行实际软件核对；必要正式回归通过后，用新的补丁版本构建发布，不覆盖已公开版本。

七、验收重点
外观：原图分辨率与常用窗口尺寸下逐项截图对照；最大化、100%/125%/150% 系统缩放时填满可用空间，按钮不被挤出窗口。
字段：后台排序、显隐、条目类型与设备/费用字段逻辑保持；截图未显示的后台字段不被擅自删除。
折叠：收起/展开、切换单证和恢复草稿后值不丢；摘要、开关、当前账户与实际输出一致；缺失必填项时定位到对应展开板块。
批量：勾选、已选数量、切换、制作、输出范围一致；不覆盖旧草稿、不误导出未选单证、不把取消或失败记为成功。
保存：自动保存真实成功、关闭重开恢复、多份草稿独立、历史与客户隔离均需验证。
输出：单独预览入口保留，电子 PDF 连续长页，打印按保存的 A4 方向自然分页；颜色、背景及签章保持一致。
性能：首页分别测首屏呈现、数据可用与后台初始化耗时；不能只遮住原页面而保留七八秒卡顿。

八、实施与本地验收结果
正式实现：assets/document-composer.js / .css 接入 app.js 和原有填写、输出、草稿流程；未替换既有 PDF 引擎或公司资料。
独立交互 Demo：npm run demo:composer；仅使用临时数据目录，正式程序使用同一界面模块。
真实鼠标验证：六个折叠板块、顶部勾选与单证切换、保留已有独立草稿、从当前PI准备新单证、所选PDF导出和取消、返回修改、全宽及原导航恢复。
业务验证：八类单证后台字段顺序、设备与费用分支；FOB交货港直接填写；CIF集装箱条件联动；自定义30 day回显与原文保存。
输出验证：电子长页、A4自然分页，背景及所选颜色与实际PDF一致，成功输出后独立归档、取消不归档。
恢复验证：真实关闭重开三进程验证通过；历史、客户和原草稿隔离。
首页验证：隔离876产品/17单证，后台同步阻塞前已显示缓存统计；无大备份重复读取或过早上传，应用锁与冷缓存恢复通过。
发布条件：本轮实际提交的GitHub Actions完整回归和安装包构建成功，公开版本/元数据/提交一致；未进行用户桌面覆盖安装。
